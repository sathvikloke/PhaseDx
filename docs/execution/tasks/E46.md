# E46 — Execute only a specifically adjudicated result-changing correction

Owner: **User / authorized CPU executor (Codex or independently launched Claude)**. Lane: conditional repair. Priority: conditional. Status: optional.

Dependencies: [H07](H07.md).

## Inputs

A concrete scientific defect record, affected family/endpoint and approved correction specification

Resolve batch locators through [source map](../source_map.json) and [input configuration](../INPUTS.md). Historical inputs are read-only.

## Deliverables and owned paths

Versioned corrected output and explicit old/new impact table

## Execution

1. Run only affected computations from fixed inputs and preserve the original results.
2. Bind the correction to the defect and retain all attempts; do not add samples, seeds, hyperparameters or outcomes to chase significance.
3. Return correction evidence for a new scoped review; downstream tables update only after that review.

## Acceptance

The identified defect is resolved and its exact numerical/scope impact is visible. This is dormant without a real defect.

Resource profile: depends on defect; must be specified. Actual runtime is unknown until measured; no invented nine-hour compute estimate.

**Conditional scope:** do not schedule automatically. Record the scientific/operational reason and activate only this task when that condition actually exists.

Return: exact command and environment, input/config identities, output locations, exit status, failures and measured timing. Mark execution complete only with evidence; scientific acceptance is separate. If one input is missing, name it and backfill another ready task.
